- Offline downloads: the offline-media function (logic in handler.ts, entry in index.ts) packages media into AES-GCM 1 MB chunks (private offline-packages bucket; content keys wrapped with the versioned OFFLINE_MASTER_KEY in backend-only offline_package_keys) and issues ECDH P-256 + HKDF-SHA256 + AES-KW device-bound licences (alg "A256KW"; older AES-GCM-wrapped licences still unwrap until they expire); the client stores only ciphertext — chunks in OPFS lmk-secure/<packageId>/<index> when writable, else IndexedDB lmk_secure_downloads (each package records its backend; device key and manifests stay in IndexedDB) — and plays via the service worker /__offline/<songId> (alias /offline-stream/<packageId>) range route, then MediaSource chunk streaming, then an in-memory copy of the current item only as last resort; src/lib/downloadManager.ts stays the public API — why: copied storage is unplayable, packages are reused per exact media version, and existing callers keep working.
- Keep the service worker's stream decryption and range parsing (public/serviceworker.js) in step with crypto.ts, policy.ts parseRange and store.ts layouts — why: both read the same database and key derivation.
- Licence checks run in order: signed in → device owned → not revoked → per-user hourly request limit → entitlement; renewals are batched (≤60 packages per request) and the queue waits on 429 instead of failing — why: the limit counts requests, so batching keeps full-history restores and renewals within it.
- The account library (downloads) is soft-deleted via deleted_at and streamed to devices with Realtime; reconciliation lives in policy.ts reconcile() — why: removals must reach every device within seconds and a re-save must win over an older removal.
- Pure rules (resume, repair, range, reconcile, batching) live in policy.ts with Vitest coverage; the backend handler takes its client as a dependency and is covered by handler_test.ts (Deno) — why: every rule is testable without real data.
- Download controls are shared: DownloadButton (per song), DownloadAllButton (lists), AlbumSaveButton (album cards) read state via useSecureDownloads/useSongDownload and gating via useSaveSong — why: every screen shows the same states, labels and Premium rules.
- The service worker skips all localhost traffic, so production offline tests must use 127.0.0.1 — why: keeps dev servers uncached.
